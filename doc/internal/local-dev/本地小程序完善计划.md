# 传之贝本地运行完善计划

本文档面向只在本地运行和演示的开发方式，目标是让微信小程序、Spring Boot 后端、MySQL/Redis 和演示数据形成稳定闭环。

## 当前项目边界

- 小程序前端：`chuanzhifron`
- 主后端 API：`chuanzhiback/demo`
- 可选后台管理：`chuanzhiback/ruoyi-admin`，本地小程序演示阶段先不作为主线
- 默认本地后端地址：`http://localhost:8001`
- 小程序开发配置：`chuanzhifron/utils/env.js`

## 第一阶段：本地启动闭环

目标：任何改动前后，都能快速确认本地服务是否可用。

1. 启动 MySQL 和 Redis。
2. 确认本地数据库存在：`intangible_heritage`。
3. 启动后端：

```bash
cd chuanzhiback/demo
./mvnw spring-boot:run
```

4. 在仓库根目录执行冒烟检查：

```bash
./scripts/local-smoke.sh
```

也可以在小程序目录执行：

```bash
cd chuanzhifron
npm run smoke:local
```

当前冒烟检查覆盖：

- `GET /actuator/health`
- `GET /api/home/debug-info`
- `GET /api/home/data`
- `GET /api/news/recent`
- `GET /api/heritage/recommended`
- `GET /api/banners`
- `GET /api/ar/projects`

## 第二阶段：演示数据稳定化

目标：新建或清空本地数据库后，小程序首页、列表、详情、沉浸页都有可展示数据。

优先整理这些数据：

- 测试账号：至少 1 个普通用户
- 新闻：5 到 10 条，含封面、标题、发布时间、正文
- 非遗项目：国家级、省级、本地代表项目各若干
- 传承人：至少 5 个，包含头像、技艺、简介、地区
- 视频：至少 3 个可播放条目
- 活动：至少 3 个可预约或报名条目
- 轮播图：3 到 5 张
- AR/沉浸项目：至少 3 个，包含封面、模型或体验入口

数据应优先进入后端的初始化 SQL 或幂等 seed 逻辑，避免只依赖手工数据库操作。

## 第三阶段：小程序主链路完善

目标：用户从首页进入任意主功能，都能看到数据、执行操作、回到个人中心查看结果。

优先链路：

1. 登录/注册
2. 首页搜索、通知、轮播、文化热点、精选非遗
3. 非遗列表和详情
4. 收藏和取消收藏
5. 传承人详情和预约
6. 我的收藏、我的预约
7. 个人资料编辑和头像上传
8. 沉浸体验项目、体验记录

每个页面需要统一具备：

- 加载状态
- 空状态
- 接口失败提示
- 未登录跳转登录
- 图片或视频加载失败兜底

## 第四阶段：后端接口契约统一

目标：前端不再为每个接口单独猜字段。

建议统一：

- 普通响应：`success`、`message`、`data`
- 列表响应：`list`、`total`、`page`、`pageSize`、`hasMore`
- 认证失败：HTTP 401，并返回明确 `message`
- 权限不足：HTTP 403，并返回明确 `message`
- 资源不存在：HTTP 404，并返回明确 `message`

优先写清楚这些接口组：

- 首页：`/api/home/*`
- 新闻：`/api/news/*`
- 非遗：`/api/heritage/*`
- 传承人：`/api/inheritor/*`
- 收藏：`/api/user/collections/*`
- 预约：`/api/user/bookings/*`
- 沉浸：`/api/ar/*`
- 用户：`/api/auth/*`、`/api/users/*`

## 第五阶段：本地质量检查

每次完成一个功能后，至少执行：

```bash
cd chuanzhifron
npm test
npm run lint
```

```bash
cd chuanzhiback/demo
./mvnw test
```

后端服务启动后，再执行：

```bash
./scripts/local-smoke.sh
```

## 推荐执行顺序

1. 固化本地启动和冒烟检查。
2. 整理演示数据。
3. 打通登录、首页、非遗详情、收藏、预约、个人中心。
4. 完善沉浸体验和 3D 演示。
5. 再考虑是否接入 `ruoyi-admin` 做本地数据管理。
